# T-014 Scout 上下文策展移植（spike 先行）

风险等级: standard
状态: active
关联: C-008 ④（Scout spike 先行；依赖 T-012 素材管道）

## 背景与目标

东家裁定 Scout 纳入对齐、spike 先行（不可承载须回报再定）。Scout = 用执行者模型跑第二次 LLM 调用对会话上下文做策展（manifest 分组 → 选组 → 重建 → 失败回退 legacy），pi 默认关闭。0.8.2 新增 advisorScoutTimeoutMs 配置（默认 30000ms）。

## 差距评估

- pi 侧（0.8.2）：scout.ts（选 ≤32 组 ID + ≤4KB synthesis）、scout-types.ts（manifest 上限 64KB/64 组/24KB 每组）、scout-reconstruct.ts（required 组强制保留）、scout-curation.ts（非取消失败回退 legacy）、scout-context.ts 接线。
- 依赖宿主能力：第二次 LLM stream（llm.stream 可复用 ✓）、执行者模型解析（dsh 对等缝**待核**）、会话分支条目枚举（dsh-session-query，T-012 spike 产出了结）、per-tool 策略（T-012）、TUI 状态面（dsh 无，适配）。

## 收敛方案

- **spike 首项**：① dsh-session-query 能否按 pi manifest 分组所需粒度枚举会话条目；② 执行者当前模型解析缝（agents 服务或路由配置）；两项任一不可行 → 停止并回报东家（不静默降级）。
- spike 通过后：移植 scout 协议（分组/选组/重建/回退），配置键 advisorScout.timeoutMs（默认 30000），默认关闭。

## 测试计划

- 分组/选组/重建单测（pi 用例对照）；回退路径（非取消失败 → legacy 会话）；staging 实弹策展往返。
- spike 判据与时间盒（≤2 个工作日）：通过=① dsh-session-query（或等价缝）可按 pi manifest 分组粒度枚举会话条目；② 执行者当前模型可解析（agents 服务或路由配置）。两项全过才进入实现；任一失败 → 停止并回报东家定夺，不静默降级为记录项。
- spike 预研结论（2026-09-25 主线程只读核查，判据②初步成立）：`Agent` 公开接口仅暴露 `id`，无直接模型查询缝；但会话日志的 `request/context` 事件（RequestContext，路由变更时落盘）携带 provider/model 路由元数据——从最近一条 request/context 事件可推断执行者模型，经 llm.stream 以该模型跑 Scout 策展。待 staging 实证字段形态与「未发生路由变更时的兜底」（agentDefaultModel settings 命名空间可作 fallback）。
- 必锚 AC（收敛闸门）：Scout 尚未立项 PRD 需求（spike 通过后按 AgentMap 流程立项并补 R-x/AC-y 粒度的必锚清单，届时修订本节）；当前闸门为测试锚点粒度——`test/scout.test.js` 三锚点全绿 + scout 二次调用计入用量台账（usage.test.js scout 计量）。
