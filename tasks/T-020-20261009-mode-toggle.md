# T-020 介入强度软硬模式开关（C-021）

## 背景与目标

东家裁定放宽 PRD「与 pi-advisor-flow 0.8.2 严格一致」的对齐承诺（C-021，翻案 C-007/C-008 的口径而非其裁定本体）。动机：守则是纯文本软约束，上下文压缩把咨询调用与意见原文摘要掉后，激活守则的行为语境消失，执行者趋向沉默。目标：新增配置开关 `mode`，控制顾问介入强度。

- **软模式（默认）**: 与 pi 0.8.2 兼容——守则照常注入。
- **软模式增项**: 压缩/重写事件后经 steer 送达一条守则提醒（建议性、非阻断）。
- **硬模式**: 每回合同一收口事件至多一次，插件在收口完成前强制发起收口评审（Decision 协议）。
- **硬模式裁决**: proceed 放行收口；revise/blocked 意见全文经 steer 送达并由执行者续跑。
- **硬模式失败**: 评审失败 fail-open 放行收口。

决策依据：C-021（软硬模式裁决：按 verdict 分流、failureMode 不适用收口缝、压缩提醒不设独立键）。

## 差距评估

现状（main 代码）：

- `lib/gates/index.js` 头注释明确「唯一硬门是循环门」；无收口评审监听。
- `agent/turn-stopping` 缝自 T-008 完成门评审后退役。
- 该缝载体契约 `{turn, signal, agent}` 已实测在案（T-008 终态证据）。
- `lib/config.js` 无 `mode` 键；`lib/settings.js` Schema 无该键（双写义务两处都缺）。
- `lib/consultation.js` entry 枚举为 `['tool','manual','gate']`（lib/consultation.js:274）。
- Decision 协议问句与解析路径仅挂 `gate` 入口。
- `lib/delivery.js` steer 通道通用，可直接承载守则提醒与评审意见。
- `lib/observer.js` reset 类事件缝在 lib/index.js:494-505（压缩/重写重置观察器），是软模式提醒的挂点。
- 测试现状 178/178 全绿（T-010 后基线），`tools/agentmap_lint.py --report` 全绿。

差距清单：

1. `mode` 配置键：config.js 解析器与 settings.js Schema 双写。
2. 收口评审：entry 枚举扩 `turn-review`。
3. 收口评审：新增收口问句（英文、Decision 协议）。
4. 收口评审：新增 `handleTurnStopping` 处置器（去重、裁决分流、fail-open）。
5. 收口评审：lib/index.js 接线。
6. 压缩提醒：reset 缝后 steer 守则提醒（英文文案，对齐守则词汇）。
7. 状态面：status.js 快照含介入强度与收口评审计数；`/advisor gates` 回读。
8. map 层已演进（PRD R-01-009、SOLUTION 门控/咨询/横切/运行时语义、DOMAIN 术语、RATIONALE C-021）——本 task 承接实现。

## 收敛方案

1. **配置**：
   - `INTERVENTION_MODES = ['soft','hard']`、`DEFAULT_INTERVENTION_MODE = 'soft'`。
   - 顶层键 `mode` 经 `parseEnum` 校验，非法值拒绝并入既有 errors 路径；KNOWN 列表补 `mode`。
   - `lib/settings.js` Schema 补 `z.union(['soft','hard']).default('soft')`。
2. **咨询入口**：
   - entry 白名单扩 `'turn-review'`。
   - `TURN_REVIEW_QUESTION`（英文，要求顾问以 `Decision:` 首行裁定执行者本轮行为）。
   - Decision 行解析条件从 `entry === 'gate'` 扩为「gate 或 turn-review」。
   - `turn-review` 意见不入意见账本（与 gate 同口径）。
   - `turn-review` 用量照常记 `entry: 'turn-review'`。
3. **收口评审处置器**（lib/turn-review.js，纯逻辑 + 接线缝注入）：
   - 触发前置：`config.enabled === true` 且 `config.mode === 'hard'`。
   - 触发前置：`agent/turn-stopping` 载体有效。
   - 去重：per-session `reviewedTurns` Map（sessionId → 已评审 turn 标记）。
   - 去重语义：同回合同一收口事件至多一次评审；已评审 turn 的后续派发直接放行。
   - 同步咨询（await，受 `callTimeoutMs` 硬上限约束）。
   - 裁决分流：proceed → 放行收口（意见全文仅 info 日志）。
   - 裁决分流：revise/blocked → `delivery.steerAdvice(意见全文)`（steer 即反对收口、执行者续跑）。
   - fail-open：咨询失败（超时、空意见、预算耗尽、呈现失败、处置器异常）一律放行收口。
   - fail-open 留痕：失败经 info 级日志记录；处置器永不掷出。
   - 计数：`decisionStats` 增收口评审计数（proceed/revise/blocked 独立于循环门计数）。
4. **压缩提醒**：lib/index.js reset 分支在 `observer.reset` 后追加。
   - 触发条件：`config.mode !== 'hard'`（软模式缺省开启）。
   - 送达形态：`delivery.steerReminder(sessionId, GUIDELINE_REMINDER_TEXT)`。
   - 文案英文，复述三类守则时机；送达失败 contained。
5. **接线**：`ctx.on('agent/turn-stopping', handler, { global: true })`。
   - 监听器不使用 next()（事件非 waterfall，与 T-008 实测形态一致）。
6. **状态面**：status.js 快照增 `mode` 与收口评审计数；`/advisor gates` 回读 mode。
7. **测试**（锚定 R-01-009/AC-nn）：
   - mode 解析：缺省 soft、合法值透传、非法值拒绝且原因可查。
   - 硬模式触发：收口即同步咨询一次。
   - 硬模式处置：proceed 不 steer；revise/blocked steer 全文。
   - 去重：同回合同一收口事件二次派发放行且不重复评审。
   - fail-open：consult 拒绝、超时、空意见、预算耗尽一律放行收口并留痕。
   - 软模式：不发起收口评审。
   - 软模式提醒：压缩事件送达守则提醒一次；硬模式压缩事件不提醒。
   - 回归：soft 模式全部既有行为不变（基线全绿）。
