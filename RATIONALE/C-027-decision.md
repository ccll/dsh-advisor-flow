# C-027 出站链归一化：合并标题生成式、建档补插与证据修复收窄

日期: 2026-10-13

#### 上下文
push 被 pre-push 双层拦截：commit-msg 拒自定义中文合并标题 `🔀 合并`（配对表无此对、正文缺三节，且「Merge 使用 Git 生成标题」条款本就要求生成式）；历史完整性检查另拒三点——T-019 任务文件在关闭提交才首次出现（凭空终态）、合并首亲视角 T-027 凭空终态（重命名豁免要求首亲侧已有同名后缀文件）、T-028 终态后修改含非 `- commit:` 形状的哈希行。校验器与 lint 属 AgentMap 运行时契约（SHA256 钉死），项目侧不得改写。

#### 决策
对未推送的自有链做脚本化归一：合并标题改 `Merge branch ...` 生成式；adapt 侧与 main 侧各补插一枚 T-019 active 建档提交（实施与关闭提交树不变，建档内容取关闭文本回翻状态行）；合并重定亲使重命名豁免成立；后代按序重放；T-028 证据修复收窄为 `- commit:` 单行哈希替换（证据指针修复规则允许的唯一形状），账本 note 哈希同步。

#### 被否方案及原因
- 校验器补 🔀 配对与合并正文豁免：框架运行时文件被契约钉死，项目侧改写即 lint 失败；通用缺口走 AgentMap 上游。
- push --no-verify：绕过门禁，埋漂移。
- review 行与子 bullet 哈希一并修复：证据修复逐行限定 `- commit:` 形状，prose 哈希按原样保留；全量改写即再次违规。
- --rebase-merges 交互重写：依赖编辑器；commit-tree + cherry-pick 每步以树比对机械验证。

#### 影响面
T-019、T-027、T-028（证据链与出站历史）；CONVENTIONS（提交规范，无内容变更）。
