# C-033 核心文档上限定值 30000 token，以分片方案行承载超限过渡

日期: 2026-10-14

#### 上下文
2026-10-14 bootstrap 核验发现 CONVENTIONS 本地参数未登记「核心文档上限」，agentmap_lint 的核心文档预算闸门停用——核心文档（PRD+SOLUTION+DOMAIN+CONVENTIONS+AGENTS.md 合计 111392 B）超限不可见。93 条 AC 体量下核心文档总量已远超任何合理上限，需定值登记激活闸门，并为既成超限给出合法过渡通道。

#### 决策
CONVENTIONS「AgentMap 本地参数」登记 `- 核心文档上限: 30000 token`（按 3 B/token 换算 90000 B）与 `- 核心文档分片方案: SOLUTION.md 按子系统专题下钻分片，重组 task 立项时定具体落点`；超限降为告警，重组完成删分片行恢复硬校验。

#### 被否方案及原因
- 不设上限：预算闸门永久停用，超限不可见，违背「规范优先做成可执行检查」。
- 按现况总量定上限（固化超限）：闸门失去倒逼重组的作用，上限形同虚设。
- 暂不定值待重组后一次到位：告警正是推动重组的常驻机制，推迟登记只延长超限不可见期；且分片重组的触发条件（真实阅读/并发冲突）与登记告警并不冲突。

#### 影响面
校验器实现与自测；无对应 PRD 需求 R-ID 与产品子系统规范名，承 C-016 复审备注确立的校验器过程基建格式豁免先例；无执行 task（东家指令直办，登记见当日 CONVENTIONS 本地参数变更与配套文档提交）。登记后 lint 常驻预算告警，重组完成删除分片行即恢复硬校验。
