# C-019 证据指针修复升格为框架 canonical 规则：本条废止 C-018 的「不上移」裁定

日期: 2026-10-08

#### 上下文
C-018 将豁免废止后，其残余风险（终态不可变与证据可在 amend 后重新互斥、无机械出口）仍然成立：冲突源于框架两条规则自身的语义边界不清，而非项目特有偏好。进一步分析明确：终态不可变真正保护的是语义（状态、结论、验收点、需求引用），证据哈希只是定位指针；把「指针可达性修复」澄清进规则本体，两规则各归其位，冲突在定义层消失，无需例外叙事。东家授权按此思路改写上游框架（2026-10-08 会话指令）。

#### 决策
框架 canonical AGENTS.md 新增「证据指针修复」规则：终态 task 的 `- commit:` 证据行允许悬空修复——仅限不可达哈希替换为可达哈希，方向由校验器机械判定，状态、行数与证据行位置保持不变，其余终态后编辑仍拒绝；重排边界不再表述为唯一例外。校验器同步携带机制并挂接现场与历史两轴。本条废止 C-018 中「不上移框架模板」的裁定，C-018 其余裁定（升级采纳、不回移植仓库副本）维持。

#### 被否方案及原因
- 维持废止、依赖过程纪律：死锁场景无机械出口的残余风险仍在，修复义务无规则承载；事故虽低频（全量历史重放仅一处），但形态可机械判定，值得框架级收口。
- 仅回移植仓库副本、框架不动：每次框架升级重复回移植的成本永不收敛，且规则与实现分居两层，语义归属模糊。
- opt-in 声明启用：引入参数位与实现分支，把一个框架级逻辑矛盾的解法降格为项目配置。

#### 影响面
校验器实现与自测；无对应 PRD 需求 R-ID 与产品子系统规范名，承 C-016 复审备注确立的校验器过程基建格式豁免先例；无执行 task（东家裁定沿用仅 RATIONALE 记账口径）。上游变更由 agentmap-bootstrap 仓库承载并同步 canonical 哈希钉表；本仓库经 bootstrap 拉入，C-018 所记「重新互斥时以东家裁定为唯一出口」的死锁无出口残余风险随框架规则化解除。

补充（东家采纳复审意见）：规则只机械校验替换方向，不校验替换哈希是原提交的语义后继；悬空哈希可被替换为任何可达提交，反查链会静默降级。既有惯例（实现与关闭提交正文引用 task 标识）为自然修复提供兜底；机械断言列为后续增强方向，登记 TODO。
