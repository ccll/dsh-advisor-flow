# C-017 failureMode 默认值偏离 pi：block-session 改为 block-tool（东家翻案裁决）

日期: 2026-10-01

#### 上下文
C-008 ② 将阻断模式默认定为 block-session（严格对齐 pi 0.8.2）。其后的生产证据表明该默认把门审基础设施故障放大为会话级不可恢复拒绝：① 顾问模型对 Decision 协议的输出合规率非零失败——同协议 40 次复现实测约 12.5% 回复不合规（中文漂移如「决策：修订」或正文为空），对抗性 Decision 解析器 fail-closed 判为咨询失败（missing-decision）；② 2026-09-30 深夜真实会话因门审咨询失败命中 block-session 默认处置，会话进入内存封锁态后一切工具调用（含只读）被永久拒绝，无解除手段、跨回合不恢复，整会话报废。T-015 已修复词汇识别根因，但「咨询失败率非零」是顾问模型侧的常驻属性：咨询失败与 advisor 实质拦截共用同一处置档位，意味着小概率基础设施故障即可造成全会话不可逆报废——封锁属会话级不可逆动作，其默认触发条件不应挂在故障率非零的咨询链路上。东家拍板翻案（2026-10-01 会话指令）。

#### 决策
failureMode 默认值从 block-session 改为 block-tool——咨询失败与 blocked 裁决都只拒绝当前这一次工具调用，不再封锁整个会话；三个枚举值（warn-and-continue | block-tool | block-session）与处置语义本身不变，仅默认值变更。本条废弃 C-008 ② 中 failureMode 默认值的裁定，C-008 其余裁定维持。

#### 被否方案及原因
- 维持对齐 pi 默认（block-session）：严格一致口径已被生产证据压倒——失败率 12.5% 使封锁成为小概率必然事件而非尾部风险；「对齐」以分歧账本记账为合法形态（先例 C-015），不再构成默认值的否决理由。
- 分流处置（咨询基础设施故障降级放行/拦截、advisor 实质拦截维持封锁）：改变处置语义需门引擎按失败类别分档，超出本次默认值变更边界；且失败分类（解析失败/超时/预算耗尽 vs blocked 裁决）的档位映射本身待议——留作 TODO 待裁决项，不实施。
- 增加 unblock 命令或跨回合自动恢复封锁态：只缓解不消除——「一次咨询失败即封锁」的默认风险面仍在，且解除机制属封锁语义的另一待议项，不与本裁决捆绑。
- 默认 warn-and-continue：最保守方向，但 blocked 裁决与咨询失败都不产生任何拦截，循环门硬门形同虚设，与引入循环门的目的相悖；block-tool 在「保留硬门拦截」与「不放大为会话级报废」之间取平衡。
