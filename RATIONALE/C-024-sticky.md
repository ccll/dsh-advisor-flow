# C-024 设置卡保存模型选 sticky 常驻而非自动保存

日期: 2026-10-14

#### 上下文
东家反馈：web 设置卡展开表单约 11 个控件，保存按钮固定在表单末尾，滚动编辑后按钮不可见，用户易误以为修改已生效而直接关闭页面（既有插件两种先例并存：手动保存与即时生效）。需要在该卡上裁决保存交互模型。

#### 决策
保留「暂存 patch + 显式保存」模型，footer 按钮组改 sticky 常驻于滚动视口底部，并以头部「未保存」徽标显性化未保存状态（折叠态保留）。

#### 被否方案及原因
- 全量自动保存（每改一项即写）：
  - 切换提供方级联清空 model 与 effort（card-state 三级联动）。
  - 「已启用但未选模型」是编辑必经的中间非法态。
  - 该状态下自动保存连续被宿主校验拒绝。
  - 关键词与 maxTokens 输入按击键触发 onChange。
  - 自动保存须为此引入防抖或失焦语义。
  - 与三形态回执叠加后，错误提示噪声大。
- 离散控件即时保存 + 文本失焦保存的混合模型：
  - 两种交互模型并存，心智负担大。
  - 级联中间态问题同样存在。
  - 收益不抵复杂度。

#### 影响面
R-02-001/AC-09、AC-10；web 设置卡（T-024）。
