# C-014 会话词汇识别权归位：宿主运行时词汇表为权威，手工白名单降级为兜底集

日期: 2026-09-29

#### 上下文
生产故障实证：宿主按配置追加的 `subagent/model-selection-policy` 与 `session/end-seed` 均为宿主已知词汇且追加不带 ignorable，但被会话脉络重建的 staging 观测快照白名单（12 项，远小于宿主词汇全集）判为未识别必需事件 → fail-closed 抛错 → 门审失败 → 会话级全工具拒绝（两个工作区共 50 次真实拒绝；此前 `request/header`、`tool/call` 为同型历史发作，同一缺陷类随宿主词汇增长反复发作）。fail-closed 契约本身正确（T-012 spike 定稿、宿主持久层同款契约），错在「已识别」的判定权威是手工快照而非宿主运行时。
#### 决策
非表面词汇跳过集以宿主运行时词汇表为权威：可达时动态导入宿主已知事件词汇推导（宿主词汇增长自动跟随）；不可达时回落兜底集（原快照全集 + 本次实证类型）；fail-closed 仅保留给宿主词汇也不认识的类型。部署前提与实现细节落 SOLUTION#素材装配器与 task T-015。
#### 被否方案及原因
- 仅扩白名单（补实证类型了事）：词汇再增长即复发，同型已四次发作；治标。
- 静态导入宿主词汇模块：部署链接缺失时插件引导直接失败（整插件瘫痪），劣于兜底降级。
- 复制宿主词汇表入项目：副本随宿主升级漂移，重新引入「快照滞后宿主」的同缺陷类。
- 改 failureMode 默认为 warn-and-continue：属门处置策略权衡而非本缺陷根因，且改变 R-01-005 已确认语义，不入本变更。
