# C-021 介入强度软硬模式：放宽 C-008 严格一致口径（东家翻案裁决）

日期: 2026-10-09

#### 上下文
运行观察发现：软约束守则的遵循率随会话推进衰减——上下文压缩把此前的咨询调用与意见原文摘要掉，激活守则的行为语境（调用证据、意见反馈循环、近因记忆）随之消失，执行者在压缩后趋向沉默。守则是纯文本软约束，宿主无强制力，该衰减是模型行为现象而非指令丢失。东家裁定放宽「与 pi-advisor-flow 0.8.2 严格一致」的 PRD 承诺，引入配置开关控制顾问介入强度：软模式保持 pi 兼容的建议语义，硬模式在回合收口缝（`agent/turn-stopping`，T-008 已实测载体契约）强制发起一次针对本轮行为的顾问评审。

#### 决策
新增顶层配置 `mode: soft|hard`（缺省 `soft`）。软模式行为 = 现行守则注入 + 压缩/重写事件后经 steer 送达一条守则提醒（建议性、非阻断、不发起咨询）。硬模式行为 = 每回合同一收口事件至多一次：插件在收口完成前同步发起收口评审（Decision 协议三值裁决）——proceed 放行收口；revise 或 blocked 使意见全文经 steer 送达、执行者带意见续跑；评审失败（超时、空意见、预算耗尽、呈现失败）一律放行收口（非阻断）。硬模式不适用 `failureMode`（收口缝无受守护工具调用可拦截）。PRD 愿景行同步修订：严格一致承诺收窄至软模式。

#### 被否方案及原因
- 无开关直接把守则升级为强制评审：改变默认行为，破坏「软模式与 pi 严格一致」的对齐基线，且把每轮评审成本强加给全部用户。
- 压缩提醒独立配置键：压缩低频、提醒无争议，独立键徒增配置面（YAGNI）。
- 收口评审沿用 `failureMode` 三档处置：收口缝无工具调用可拦截，`block-tool`/`block-session` 无对应处置点；按裁决分流（proceed 放行 / 非 proceed 意见续跑）语义自洽。
- 续跑后同回合再次收口重复评审：形成评审—续跑—再评审循环，违背非阻断与预算纪律；同一收口事件去重、同回合至多一次。

#### 影响面
R-01-009；门控服务（收口评审处置）、咨询服务（turn-review 入口与素材）、会话观察（压缩提醒）、配置与状态服务（mode 配置与状态回读）。
