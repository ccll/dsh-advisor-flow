# C-035 语义行统计登记系统托管豁免，major 审核证据补机读锚点

日期: 2026-10-22

#### 上下文
T-037 累计审计（窗口 T-035 复位点后 5 提交）发现两条工作系统文实矛盾：其一，审核分档 v4 升级规定 major 审核证据为五标签，而 lint 机械核验要求所有需审 task 先有字面 `- review:` 行——五标签齐备仍报缺失；其二，lint 内置系统托管豁免（工作系统本体文件与验证门禁脚本免计语义行）未在 CONVENTIONS「语义行排除路径」登记，语义行触发口径与文档承诺不一致。

#### 决策
按 CONVENTIONS「文字规范与可执行检查冲突时以检查为准并修正文字」：机读锚点约定落项目层——CONVENTIONS 代码审核章明确 major 终态证据除五标签外记一行机读锚点 `- review: <审核方>｜<结论>`；语义行排除路径登记系统托管豁免（AGENTS.md、CONVENTIONS.md、工作系统工具脚本、提交校验脚本、.githooks/**），理由是防工作系统本体升级提交自触发累计审计窗口、避免只触系统文件的 task 恒测 0 使机械升档失灵。

#### 被否方案及原因
- 反向修检查、把系统本体计入 300 行触发口径：工作系统升级提交体量常超 300 行，会把每次框架刷新都变成强制审计，审计间隔失去「跨改动视角」的节奏意义；且上游托管文件由 bootstrap 刷新，仓内无权收敛其行数。
- 把 `- review:` 机读锚点改为机械解析五标签自由文本：解析自然语言结论不可靠，机读锚点一行定式是「规范优先做成可执行检查」的既有约定。

#### 影响面
R-01-009 · 子会话审核豁免（T-037）；CONVENTIONS.md 本地参数（语义行排除路径、代码审核章）；执行 task T-037。
