# C-016 终态任务证据可达性修复豁免：悬空 commit 证据行可替换为可达提交

日期: 2026-10-01

#### 上下文
公开发布推送 GitHub 时，pre-push 历史不可变门禁拦截全量 outgoing 历史（main 此前从未推送过任何远端，全部提交受检）：T-010 终态后的一次证据修正提交（2026-09-24）把终态证据中被 amend 改写销毁的提交引用替换为可达提交——不修复则违反「终态证据必须指向可达提交」校验，修复则违反「终态任务不可变」校验，两规则在 amend 场景下不可能同时满足，属契约内部矛盾；该提交当时因提交环境未挂钩子而漏检入库（全量历史逐一模拟核验，仅此一处违规）。东家裁定走门禁契约修订（闸口 2026-10-01 会话确认），否决全量重写历史。

#### 决策
校验器新增窄豁免：终态任务的编辑仅当同时满足——终态不变、差异仅限 commit 证据行、哈希一一对应替换且有效变更非空、被移除哈希均不可达（HEAD 祖先判定）、新增哈希均可达——时放行；提交现场检查与推送历史检查同口径。豁免不改变终态语义，只修复审计反查链（git blame → commit → task）的悬空指针。

#### 被否方案及原因
- 全量重写历史并以新旧哈希映射替换全部 task 证据行：一百五十余个提交重写使全部终态 task 的证据哈希级联失配，风险与动作远超收益，且不解决契约自身矛盾。
- 绕过门禁推送：直接破坏验证门禁权威性，不做。
- 收窄可达性校验放行悬空哈希：审计链断链比形式违规更伤，可达性要求优先保留。
- 仅对本次违规提交做单点 grandfather：白名单式特例不可维护，同形态未来修复仍会被拦；按形状（差异面 + 可达性方向）判定可机械执行。

#### 影响面
校验器实现与自测；系统纪律文本被规范哈希钉定不随本次修改，豁免以本条与校验器实现为契约载体，框架升级覆盖校验器时须回移植（T-017）

补充（2026-10-01，复审备注）：本决策属 AgentMap 校验器过程基建，不对应任何 PRD 需求 R-ID 与产品子系统规范名，故影响面不以 `R-gg-nnn · 子系统规范名` 格式承载，改以执行 task（T-017）为影响面载体——此为对条目格式的显式豁免说明，非无意识偏离。
